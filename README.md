# Seventwos Workspace for iOS

Seventwos Workspace for iOS is the native iOS client for the Seventwos workspace. It is built on top of a fork of [Element X iOS](https://github.com/element-hq/element-x-ios) and is being evolved for people and agents to communicate and collaborate over [Matrix](https://matrix.org/).

The project retains Element X's native-client approach: SwiftUI over the [Matrix Rust SDK](https://github.com/matrix-org/matrix-rust-sdk), exposed to Swift through its bindings. The shared Rust core provides Matrix synchronisation, local state, and end-to-end encryption while the application remains native to iOS.

## Status

This repository is in transition from its Element X foundation to a separately authored Seventwos application layer.

The current code includes inherited Element X iOS code, branding, and configuration. This fork redistributes that code under the GNU Affero General Public License v3 and must not be represented as an independently authored Seventwos implementation. The transition will replace the inherited application layer with Seventwos code while retaining the native-client architecture and the Apache-2.0 Matrix Rust SDK.

## Architecture

The intended iOS implementation includes:

- Swift and SwiftUI.
- Matrix Rust SDK integration through Swift bindings (via UniFFI).
- Client-side Matrix end-to-end encryption.
- Secure credential storage in the iOS Keychain.
- Background synchronisation.
- Apple push notifications for encrypted messages.

Element X is the upstream foundation and architectural reference for this workspace, not the target product identity.

## Repository scope

This is the product repository for Seventwos Workspace for iOS. It is the source of truth for the iOS application code, Apple platform integrations, build and test configuration, and release preparation.

Changes in this repository should directly support the iOS client. Shared services and cross-platform product material are maintained separately; the origins and licensing of upstream-derived code are documented below.

## Fork separation and where we work

To keep selective upstream synchronisation with `element-hq/element-x-ios` tractable, the repository defines a machine-checked boundary under [`.seventwos/`](.seventwos) (`upstream-policy.json`, `upstream-path-map.json`, `upstream-invariants.json`, `upstream-state.json`, `upstream-ledger.jsonl`), validated by `ci_scripts/validate_upstream_policy.py`.

### 1. Upstream target & directory mapping (`.seventwos/upstream-path-map.json`)

- Upstream's `ElementX/` target and source root are mapped to `Seventwos/`:
  - `ElementX/Sources` -> `Seventwos/Sources`
  - `ElementX/Resources` -> `Seventwos/Resources`
  - `ElementX/SupportingFiles` -> `Seventwos/SupportingFiles`
  - `ElementX.xcodeproj` -> `Seventwos.xcodeproj` (generated by XcodeGen from `project.yml`, `app.yml`, and `target.yml`; never hand-edited).
- `Enterprise/` is an unpopulated private upstream submodule and is out of scope.

### 2. Where Seventwos work lives (the Seventwos layer)

Because `Seventwos/Sources` contains both inherited Element X Swift files and Seventwos additions, Seventwos work is structured as modular layers rather than scattered inline edits across inherited files:

- **New Seventwos screens, flows, and services (preferred extension mechanism)**:
  - Add new screens as self-contained MVVM-C folders under `Seventwos/Sources/Screens/<ScreenName>/` (using `Tools/Scripts/Templates/SimpleScreenExample/`) and new Rust SDK/service wrappers under `Seventwos/Sources/Services/<Feature>/`.
  - Wire navigation and feature entrypoints through `Seventwos/Sources/FlowCoordinators/` (`AppCoordinator.swift`, `UserSessionFlowCoordinator.swift`) so inherited screens stay close to upstream.
- **Product identity, bundle identifiers & target configuration (`product-identity`, `empty-signing-team` in `.seventwos/upstream-invariants.json`)**:
  - `app.yml` and `project.yml` — define `APP_DISPLAY_NAME: Seventwos Workspace`, `PRODUCTION_APP_NAME: Seventwos Workspace`, `BASE_BUNDLE_IDENTIFIER: org.seventwos.workspace`, and `APP_GROUP_IDENTIFIER: group.org.seventwos.workspace`.
- **Seventwos endpoints, telemetry gating & release readiness (`seventwos-endpoints`, `inherited-telemetry-disabled`, `release-readiness-fails-closed`)**:
  - `Seventwos/Sources/Application/Settings/AppSettings.swift` — configures `workspace.seventwos.org` endpoints and forbids upstream `element.io` / `vector.im` defaults.
  - `Components/Secrets/Secrets.swift` — disables inherited Sentry, PostHog, and rageshake telemetry (`nil`).
  - `ci_scripts/validate_release_readiness.sh` — fail-closed check preventing release with placeholder or upstream service configuration.
- **Design system & shared UI**:
  - `compound-ios/` and `Components/` — UI tokens (`Color.compound.*`, `Font.compound.*`, `CompoundIcon`) and reusable components.
- **Upstream sync policy & invariants**:
  - `.seventwos/` and `ci_scripts/validate_upstream_policy.py` — when introducing a new Seventwos behavioral invariant (or path/target mapping), add it to `.seventwos/upstream-invariants.json` (or `.seventwos/upstream-path-map.json`), register its enforcement in `REQUIRED_INVARIANTS` inside `ci_scripts/validate_upstream_policy.py` (with unit tests in `ci_scripts/validate_upstream_policy_test.py`), and run `python3 ci_scripts/validate_upstream_policy.py` locally because `.github/workflows/upstream-assessment.yml` only triggers policy validation when policy-scoped files change.
