# AGENTS.md

## Purpose
Seventwos Workspace for iOS: native iOS client for the Seventwos workspace (Matrix). Fork of Element X iOS, mid-transition to a Seventwos app layer (AGPL-3.0 inherited code).

## Stack
Swift / SwiftUI, Matrix Rust SDK (UniFFI bindings via SwiftPM), XcodeGen (`project.yml`), SwiftGen, Sourcery, SwiftFormat, SwiftLint, Periphery. CI: GitHub Actions.

## Layout
- `Seventwos/` main app; `NSE/` notification extension; `ShareExtension/`; `Components/`; `compound-ios/` design system
- `UnitTests/`, `UITests/`, `IntegrationTests/`, `AccessibilityTests/`, `PreviewTests/`
- `Tools/` (Scripts, Sourcery, SwiftGen, XcodeGen, Sources = `tools` SwiftPM executable)
- `ci_scripts/` CI + upstream policy validators; `.seventwos/` upstream tracking data; `Enterprise/` private submodule (may be inaccessible)
- `docs/`, `documentation/` docs; `.githooks/` git hooks; `.agent/state.md` agent state

## Adding the Seventwos layer on top of the fork (where we work)
- **Target & path mapping (`.seventwos/upstream-path-map.json`)**: Upstream `ElementX/` (`Sources`, `Resources`, `SupportingFiles`, `ElementX.xcodeproj`) is mapped to `Seventwos/` (`Seventwos.xcodeproj` is generated by XcodeGen from `project.yml`, `app.yml`, and `target.yml`).
- **Prefer modular screens/services + flow coordinator wiring over in-place edits**:
  - Add new Seventwos screens as self-contained MVVM-C units under `Seventwos/Sources/Screens/<ScreenName>/` (template: `Tools/Scripts/Templates/SimpleScreenExample/`) and new service proxies under `Seventwos/Sources/Services/<Feature>/`.
  - Wire new flows in `Seventwos/Sources/FlowCoordinators/` (`AppCoordinator.swift`, `UserSessionFlowCoordinator.swift`) rather than scattering inline changes across inherited Element X screens.
- **Identity, endpoints, and telemetry invariants (`.seventwos/upstream-invariants.json`)**:
  - Product display names and bundle IDs (`org.seventwos.workspace`) live in `app.yml`.
  - Homeserver and service defaults (`workspace.seventwos.org`, never `element.io` or `vector.im`) live in `Seventwos/Sources/Application/Settings/AppSettings.swift`.
  - Inherited Sentry/PostHog/rageshake endpoints stay `nil` in `Components/Secrets/Secrets.swift` (enforced by the `inherited-telemetry-disabled` invariant in `ci_scripts/validate_upstream_policy.py`, while `ci_scripts/validate_release_readiness.sh` rejects inherited upstream domains and placeholder release values).
- **Register new divergence in `.seventwos/`**:
  - When introducing a new Seventwos behavioral requirement or path mapping that must survive upstream syncs, add it to `.seventwos/upstream-invariants.json` or `.seventwos/upstream-path-map.json`, add the corresponding check to `REQUIRED_INVARIANTS` in `ci_scripts/validate_upstream_policy.py` (and `ci_scripts/validate_upstream_policy_test.py`), and run `python3 ci_scripts/validate_upstream_policy.py` (since `upstream-assessment.yml` only runs validation when policy-scoped paths change).

## Branching
`main` is the only long-lived branch (trunk-based): branch from and open PRs into `main`, keep branches short-lived (`feat/`, `fix/`, `chore/`, or `card/<id>-<slug>` for agents) and squash-merge. `develop` is being retired; until it is removed CI runs for both `main` and `develop`, but start no new work on `develop`. Agents work on `card/<id>-<slug>` branches; never push directly to main. Changes land via PR under the [owner-led merge rules](.github/copilot-instructions.md#pull-requests-and-merge-authority) and [autonomous-review policy](.github/instructions/autonomous-review.instructions.md). `CODEOWNERS` records ownership, not an additional approval gate; check the live branch rules and preserve required checks, applicable independent review, thread resolution and action authorisation. Al (CPO) signs off Forgejo progression only, not every GitHub PR.

## Versioning (existing practice)
- Current convention is CalVer `YY.MM.PATCH` (e.g. `MARKETING_VERSION: 26.09.2` in `project.yml`).
- Release tags are `release/YY.MM.PATCH` (latest seen: `release/26.09.1`); older legacy tags are `v1.0.0.<yyyymmddhhmm>`. Plain semver `vX.Y.Z` is NOT the current convention.
- `.github/workflows/automatic-calendar-version.yml` (manual dispatch) bumps year/month and resets patch; patch bumps are done by the release script. Check these before tagging.

## UI changes need screenshots

Any user-visible change (screens, layout, styling, branding, text, flows) must include:

- An "after" screenshot of every changed screen, and a "before" screenshot when an existing screen changed.
- iOS: capture from the simulator or a CI screenshot; if impossible, say why in the PR.
- Use realistic data, not empty states.
- Attach screenshots to the Planka card and to the PR description.
- Missing screenshots = not approved.

## Technical conventions (iOS)

### Code style
- SwiftLint and SwiftFormat enforce style on build; follow the Swift API Design Guidelines (`ID` not `Id`, `URL` not `Url`, `configuration` not `config`).
- Import `SwiftUI`, not `UIKit` or `Foundation`, in UI code.
- Member order: properties, `init`, functions. Views: properties, `init`, `body` first, then helpers.
- Comments explain why, not what. `///` docs open with a summary of what the symbol is or does.
- Logging: default `MXLog.info`, unexpected failures `.error`. Never log secrets or user content. Action enums with secret associated values conform to `CustomStringConvertible` and log only the case name.
- Strings: never edit `Localizable.strings` (generated). New English strings go in `Untranslated.strings`; access them via generated `L10n`.
- Previews: use `PreviewProvider` with `TestablePreview` for all main states (snapshot and accessibility tests are generated from them).
- Tests use Swift Testing where possible; see `.agents/skills/constrained-tests`.

### Architecture: MVVM-C
Each screen `Foo` has `FooScreenModels.swift` (ViewState, bindings, ViewAction, ViewModelAction), `FooScreenViewModelProtocol.swift`, `FooScreenViewModel.swift` (subclass of `StateStoreViewModelV2`), a SwiftUI view taking `@Bindable var context`, `FooScreenCoordinator.swift` and unit tests. Template: `Tools/Scripts/Templates/SimpleScreenExample/`.
- `StateStoreViewModelV2` (`Seventwos/Sources/Other/SwiftUI/ViewModel/`) uses Observation: `context.viewState`, `context.send(viewAction:)`, `$context.<binding>`. Older screens may still use the Combine `StateStoreViewModel`.
- View models notify coordinators through a `PassthroughSubject`; coordinators expose `actionsPublisher` to flow coordinators.
- Flow coordinators own navigation and use `StateMachine<State, Event>`. `CommonFlowParameters` is for flow coordinators only; screens get specific dependencies via their `Parameters` struct.
- Errors: SwiftUI alerts via `AlertInfo` in bindings; toasts via `UserIndicatorController` (modal indicators are not for errors).

### Matrix Rust SDK layer
- Wrap SDK objects in a protocol + proxy (`ClientProxyProtocol` / `ClientProxy`, Sourcery mock), named SDK type + `Proxy`, under `Services/<Feature>/`.
- Map SDK records/enums to app-owned Swift types (`init(rustValue:)`, `rustValue`); views never import `MatrixRustSDK`.
- Use typed `Result<T, E>`; `async` only when the Rust method is async; map FFI types to Swift ones (`String` to `URL`, timestamps to `Date`).
- Dependencies come via `init`. Pass `userSession` when 2+ of its members are needed, otherwise the single member. Singletons are a last resort.

### Concurrency
- Swift 6 language mode. The app, UnitTests and PreviewTests default to `MainActor` isolation, so skip redundant `@MainActor`; extensions are nonisolated.
- Services and data-layer types are `nonisolated` + `Sendable` when background work needs it. Never use `@unchecked Sendable` or `nonisolated(unsafe)`.
- See `.agents/skills/swift-concurrency-pro`.

### Compound design system
- `compound-ios/` provides all UI styling: `Color.compound.*`, `Font.compound.*`, `CompoundIcon(\.icon)`, `ListRow`, `.compoundList()`, `CompoundButtonStyle`, `.toggleStyle(.compound)`. Deviate only when no equivalent exists.
